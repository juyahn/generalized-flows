# Sprint Sync 티켓 브리핑 템플릿

월요일 Sprint Sync 전에 진행 중인 티켓을 한 장으로 정리할 때 쓰는 양식입니다.

## 산출물과 위치

```
08_summaries/sprint-sync-YYYY-MM-DD/
  brief.md          싱크 문서에 옮겨 쓰는 본문 (이 템플릿 형식)
```

## 무엇을 보고 쓰나

| 원자료 | 무엇을 가져오나 |
|---|---|
| 티켓별 세션의 **당일 대화** | 사용자가 리마인드하며 물은 것과 그 답. 여기서 "오늘 고민한 점"을 뽑음 |
| `04_debugging/<티켓>-*.md` 진단 노트 | 원인, 검증 수치, 막다른 길, 아직 안 한 것 |
| Jira 본문·댓글 | 고객사 Expected, 새로 달린 댓글 |
| worktree·진단 노트의 검증 절 | 수정이 검증까지 됐는지, 수정 전 → 수정 후 수치 |
| Slack | 고객사 결정이 났는지, 배포 목록에서 뺐는지 |

당일 세션이 없는 티켓은 진단 노트와 마지막 세션 결론을 쓰고, 그렇다고 본문에 적습니다.

## 본문 형식

### 1. 개요 표

| 티켓 | 지역 | 합의가 필요한 핵심 |
|---|---|---|
| CUST-NNNN | KR / JP | 한 구절 |

### 2. 티켓별 블록

```
## CUST-NNNN · 지역 · 이슈 제목

**이슈**: 한 문장. 봇이 무엇을 했고 무엇을 했어야 하는지.

**예시 대화** (대화 ID, 운영/재현 구분, agent 버전, 날짜)
  고객 → 봇 → 툴 순서로, 실제 발화와 실제 값을 그대로.
  잘못된 턴 끝에 "← 무엇이 틀렸는지".
  일본어 발화는 원문 뒤 괄호에 한국어 번역.

**원인**: 불릿 2~4개. 확인된 것과 가설을 구분. 근거 수치(n/N)를 붙임.

**수정 방향**: 고른 안, 버린 안과 이유, 수정 전 → 수정 후 수치.
  당일 고민한 점이 있으면 여기 또는 별도 소단락으로.

**합의 필요**: 번호 목록. 항목마다 누구와 합의하는지 표시.
  고객사 / 내부 / 문제 정의(범위) / 블로커·일정
```

### 3. 양식 칸별 모음

Sprint Sync 1 Pager의 칸에 그대로 옮길 수 있게 티켓별 항목을 다시 묶습니다.

| 1 Pager 칸 | 무엇을 모으나 |
|---|---|
| 목표 티켓 & 범위 · 문제 정의 사전검토 | 티켓 문제 정의와 실제 작업 범위가 달라진 것 (확장, 축소, 전환) |
| 목표 티켓 & 범위 · PM과 결과물 얼라인 | 티켓별 블록의 예시 대화(As-Is)와 수정 방향(To-Be) |
| 고객사 소통 필요사항 · 배포일정 재검토 | 고객사 결정이 필요한 것 (문구 검토, API response 정의, 운영 정보 확인, 상담 플로우) |
| 블로커 및 Risk · 작업일정/분배 재검토 | 배포 순서 제약, 다른 티켓과 같은 파일·같은 공용 환경을 쓰는 충돌 |

## 쓸 때 지키는 것

- 기한과 PR·브랜치 상태(push, CI, draft, 리뷰 대기)는 넣지 않습니다. 카드 배지에는 지역과 작업 방향만 둡니다.
- 흐름은 화살표 단계와 실제 값으로 씁니다. "보상 조회 결과가 부적절" 대신 "고객사 API 응답 [쿠폰 3,000원 · 환불 16,234원 · 재배달]"처럼 씁니다.
- 수치는 수정 전 → 수정 후로 나란히 적고, 재생(로컬)과 staged run·운영을 구분합니다.
- 오늘 고민한 점은 사용자가 세션에서 실제로 물은 질문을 기준으로 뽑습니다. 세션이 결론 낸 것과 아직 답을 받지 못한 것을 섞지 않습니다.
- 사람 이름은 누가 무엇을 했다는 사실을 적을 때만 씁니다. 합의 항목의 담당은 영역으로 적습니다.
