## 검증

| 단 | 무엇 | 결과 |
|---|---|---|
| 1 리플레이 | <어느 호출> | <n>/<m> |
| 2 로컬 에이전트 | <로컬 실행 환경> | <n>/<m> · 해당 없으면 이유 |
| 3 staged run | `<staged version>` | <링크> · 서빙 확인 <yes/no> · 케이스별 결과 |
| 4 회귀 | 회귀 suite / 골든 | <n>/<m> |

**케이스별로 적습니다.** 합산 m/n은 실패한 로케일 하나를 가립니다. 해당 없는 단은 왜 해당 없는지를 적고, 넘어간 게 아니라 판단한 것임을 남깁니다.

**대조군은 둘입니다.** 신규 분기가 열리면 안 되는 입력(true negative)과, 수정이 닿은 기존 자리(인접 플로우 무회귀). 한 라벨로 묶으면 회귀를 얼마나 덮었는지가 부풀려집니다.

**회차 수도 적습니다.** 설계를 가르면서 런타임에서만 보이는 케이스는 n≥6, 부수 확인은 n=1, 결정적 산출물로 결판나면 n=0이고 그 산출물을 증거로 답니다.

막혀 있으면 막힌 이유를 적습니다. routing 파일은 배포 전 staged run 증거가 없을 수 있고, KB는 업로드 전까지 after-fix 실행 자체가 없습니다. 둘 다 대기 상태이지 통과가 아닙니다.
